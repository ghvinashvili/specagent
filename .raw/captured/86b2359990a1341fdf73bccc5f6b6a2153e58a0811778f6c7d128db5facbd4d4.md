# The checkout is a claude-obsidian vault

The owner (2026-10-30 18:1x UTC) decided that everything moves to the plugin, made exactly as the plugin would make
it (the original words are kept in the private vault). The measurement run of the plugin was cancelled by the owner the same hour; the move is
made with the plugin's own commands, so the vault is exactly what the plugin would have made.

## The rule
- The checkout root is the vault (`.claude-obsidian.json`, `vault: "."`), `wiki/` holds its pages, `.raw/` its captured
  sources, `inbox/` what waits for an ingest, `wiki/meta/ledgers/` its source and claim ledgers, `.vault-meta/` its
  journal (`transactions/` stays local) and its lint allowlist. `.obsidian/` at the root carries the shared Obsidian
  settings; the old vault at `wiki/.obsidian` is gone. The owner opens the checkout root in Obsidian.
- The plugin comes from git: `plugins/.claude-plugin/marketplace.json` names it `obsidian-vault` with a github source
  (a third party's entry may not start with `claude-`, `claude plugin validate`), `ops/bootstrap.py`
  installs it for the checkout at project scope, `docs/roles/extensions.yaml` pins the reviewed version and
  `harness validate` fails on another one until a human reviews it. Nothing of it is enabled at user scope: what a
  session loads is decided per session (the project settings, or `--plugin-dir` at a launch).
- Every session of the checkout starts with `wiki/hot.md` (at most 500 words): `CLAUDE_OBSIDIAN_SESSION_CONTEXT=1` in
  `.claude/settings.json` makes the plugin's SessionStart hook inject it. Retrieval order: `wiki/hot.md`, then
  `wiki/index.md`, then the page; a role with the `wiki-query` skill asks it before adding anything new.
- Pages keep the template's frontmatter and also `created` and `tags` (`schemas/wiki-page.schema.json`), which the
  plugin's lint requires. A `.summary.md` summary is no page for the plugin either
  (`.vault-meta/lint-allowlist.json` excludes them); the links to the generated `wiki/graph/index.md` and to
  `wiki/plans/` (a symlink, which the plugin's scan skips) are allowlisted there.
- A page is written with the plugin's `save` skill when the session has it (a journaled operation), else with Write
  as before; `python3 ops/adopt-obsidian.py lint` (`just wiki-lint`, part of `just validate`) is clean before a
  commit, with `hidden_target_links` (links from pages to code files) as the one tolerated category.
- `python3 ops/adopt-obsidian.py --apply` moves another checkout of the template the same way, each step skipped
  when it is done; `ops/adopt-obsidian.py cli --dir` prints the plugin directory for a role's `--plugin-dir`.
